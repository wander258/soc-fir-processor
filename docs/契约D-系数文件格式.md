## 0. 这份契约管什么

它规定 **C（系数工具）产出的文件长什么样**，因为 **A 和 B 的 Verilog testbench 要直接消费它**。
格式一旦定死，C 随便改算法、A/B 随便改 RTL，三边的数据都能对得上。

**一句话：这是软件和硬件之间的数据接口。**

## 1. D1 —— `fir/coeffs.vh`：给 Verilog ``include`

```verilog
// 由 fir/fir_coeff.py 自动生成，勿手改
localparam signed [15:0] H0  = 16'sd20;
localparam signed [15:0] H1  = 16'sd20;
localparam signed [15:0] H2  = 16'sd-9;
// ...
localparam signed [15:0] H80 = 16'sd20;
```

| 约定 | 值 |
|---|---|
| 参数名 | 固定 `H0` ~ `H{NTAP-1}`（**下标从 0 开始，不补零**） |
| 位宽 | `signed [15:0]`（Q1.15） |
| 值域 | `[-32768, 32767]` |
| 行数 | 恰好 `NTAP`（当前 81）行 |
| 用途 | ``include "coeffs.vh"` 后直接用（教学版 lab 用这种） |

## 2. D2 —— `fir/coeffs.hex`：给 `$readmemh`

```
0014
0014
FFF7
...
```

| 约定 | 值 |
|---|---|
| 格式 | 每行 **4 位十六进制补码**（负数写成 16 位补码，如 −9 → `FFF7`） |
| 行数 | 恰好 `NTAP` 行 |
| 消费方式 | `reg signed [15:0] coeffs [0:NTAP-1]; $readmemh("coeffs.hex", coeffs);` |
| 用途 | **最终工程用这种**——系数可配置，TB 不该把系数编进 RTL |

> ⚠️ `.gitignore` 已排除 `*.hex`，所以 `.hex` **不会进 git**，需要时由脚本重新生成。
> `coeffs.vh` 不在忽略列表里，会被提交（和其他 lab 保持一致）。

## 3. D3 —— `fir/stim.hex` / `fir/exp.hex`

| 文件 | 内容 | 行数 |
|---|---|---|
| `stim.hex` | 输入激励（测试样本） | `NSAMP` |
| `exp.hex` | 黄金模型算出的期望输出 | `NSAMP + NTAP − 1`（**全卷积长度**） |

格式同 D2（每行 4 位十六进制补码）。

**为什么 exp 比 stim 多 `NTAP−1` 行**：全卷积要等延迟线被排空，最后 `NTAP−1` 个输出仍然非零。
测试台喂完 `NSAMP` 个样本后继续灌 0 排空，才能收齐全部 `NSAMP+NTAP−1` 个结果。

**测试台比对约定**（A 和 B 都要按这个写）：

```
第 1 个 dout_v 输出 = 全零输入的卷积结果（一个前导 0）
第 2 个 dout_v 输出 = exp[0]
第 3 个 dout_v 输出 = exp[1]
...
即：  got[i+1] 应该等于  exp[i]
```
